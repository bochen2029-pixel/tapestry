## §2 · The constraint language, and why it is not DuckDB

§9's R0 row specifies "the constraint language as scalar UDFs in DuckDB with threads pinned to one"; the QC synthesis §3.14 records the decider choosing it. **The operator rejected that dependency for this build**, and the technical case agrees with them:

§3.4 identifies a fold by "the hash of its source together with the compiler identity, the flag string and the target architecture". A third-party query planner inside the one writer's refusal decision appears in none of that tuple, so §5's "exact within a tuple" claim would rest on a library the tuple cannot name — in a store whose entire argument is that every durable structure re-derives from the tape. DuckDB is also not installed on this box, so taking it would have meant adding a dependency to make the writ work.

What replaces it **[SPEC]**:

```
amount_minor <= 500000 && (state != 3 || due_ns > now_ns)
```

- **Int64 and bool, nothing else.** No floats and no float literals — `amount_minor == 1.5` is a parse error, not a rounding question. A float comparison is not portable across host and device (falsifier 1b), and money a cap fold sums must be exact.
- **Total.** Overflow, division by zero and modulo by zero are typed evaluation errors checked *before* the operation, never traps and never wrapped values. **A constraint that cannot be evaluated refuses the write**; it never passes by default. `refuse.uneval_is_a_refusal` and `refuse.uneval_names_why` **[M]**.
- **Short-circuiting**, so `state != 0 && 100 / state == 1` is a legal constraint rather than a trap waiting for a zero **[M]**.
- **Identified by meaning, not spelling.** `program_hash` covers the opcodes, the constants, the bound column names in order, and the evaluator's version tag — not the source text. Reformatting a rule does not invalidate a pin; changing `<=` to `<` does. `expr.hash_ignores_whitespace` and `expr.hash_follows_the_operator` **[M]**.
- **Answerable.** A program records which columns it reads, so a refusal can name the offending values and §4.8's `explain_refusal` has something true to print.

Compile-time refusals are checked as a table: an int used as a constraint (`expr_not_bool`), an unknown column, an int in a boolean position, a malformed expression, a leading-zero number, a float literal — all refused when the rule is **proposed**, never when a write depends on it **[M]**.

The read path — §4.8's `query(sql, as_of_pos)` — is a separate question. Nothing in R0 through R2 needs it, and it is deliberately not answered here.

## §3 · Falsifier 20 · every field of the class map moves its pin

QC-2 F6 and QC-7 F3 measured the shipped pin blind to the predicate operator, the class id and the flags. The oracle mutates **eleven** fields one at a time — `cls`, `name`, `flags`, `cap`, `quorum_n`, `quorum_m`, `rev.table`, `rev.op`, `rev.rev`, `rev.window`, `rev.count` — and fails if any leaves the pin unmoved. All eleven move it **[M]**. A twelfth arm changes only a check expression's *meaning* and moves the pin through the program hash; the map pin follows the class pin.

The planted lie is the mixer itself: hashing concatenated fields makes `"ab"‖"c"` and `"a"‖"bc"` collide — demonstrated in the oracle **[M]** — so every field here is length-prefixed and the same two class maps do not collide.

## §4 · The write path, measured against §4.1's order

Leader check → token bucket → reply cache → constraints → build, batch, commit, acknowledge, publish.

- **A retried write applies once and answers the same thing twice.** The reply cache is keyed `(client_id, request_id)`; a retry carrying *different* facts returns the original position and hash, is counted as `duplicate_request`, and does not touch the cell **[M]**. This is one of R0's five gates.
- **Two refusal classes, and the boundary holds.** A rate-limited principal is a **counter** and writes no entry (`admit.a_fault_is_not_an_entry`, 0 refuse entries after 7 rate-limited writes **[M]**); an unknown class is an **entry** on the tape. `stale_basis` is a fault; `stale_source` is an entry. The distinction is not cosmetic: an entry is a permanent claim about a counterparty's behaviour.
- **Reversibility is derived, never declared.** A writer's declaration is checked against the pinned class map and a mismatch is refused (`reversibility_mismatch`); a missing inverse where the class requires one is refused (`no_inverse`); **an inverse on an exogenous fact is refused** — the world's own rows are not ours to undo **[M]**.
- **The seam authors verbs or nobody does** (falsifier 17). A `verb` entry whose `by` is a judge key, a seat, or a *different seam code hash* is refused `not_authored_by_seam`; only `seam:<pinned hash>` is admitted **[M]**.
- **Every tape written by these oracles verifies** with zero breaks after each test **[M]**.

## §5 · The falsifiers, planted and passing

**Falsifier 9 · the clock that does not truncate [M].** A source revision at `2^32 - 6` followed by one at `2^32 + 6`: the later one applies, `src_pos_last` keeps all 64 bits, a lower revision is refused `stale_source`, and an equal one is a counted duplicate no-op that changes no column. The lie arm shows the shipped 32-bit field inverting the order of exactly those two revisions.

**Falsifier 15 · the cap that refusals cannot spend [M].** Cap 1000; a 600 write is funded; **20 over-cap writes are refused and the accumulator stays at 600**; then a legal 400 write is funded, landing exactly at the cap. A `cap_period` tick closes the period and the next write is funded again. The lie is a mutable counter, and the oracle kills it two ways: the accumulator is derived only from committed facts, and **a transactor rebuilt from the tape alone reproduces both the cap and a bit-identical cell-table digest** — which nothing on the tape could do for a counter incremented at validation time.

**Falsifier 4 · the refusal that never silences [M].** 50 writes refused by one check; the `count` fields on the resulting `refuse` entries **sum to exactly 50** across fewer entries than refusals, so coalescing changed the entry count and not the sum. The health counters agree. The refusal names its clause (`c1`), and an unevaluatable constraint refuses with the reason inside the constraint id.

**Falsifier 17 · nothing learned disposes [M].** Above, in §4.

**Falsifier 20 · every field moves the pin [M].** Above, in §3.

## §6 · Deltas against the blueprint

1. **No DuckDB in the write path** (§2). TAPESTRY's own evaluator, source-hashed into the fold identity. The operator's decision; the reason is §3.4's own definition of a fold's identity.
2. **§3.2's `Cell` struct is 120 bytes, and its own `static_assert(sizeof(Cell) == 128)` does not compile.** Counting the printed fields: 56 bytes of clocks, 12 of floats, 12 of `uint32`, 4 of `uint8`, then `root_pin` needs 8-byte alignment and four bytes of padding appear after `gear` that the blueprint's arithmetic never accounts for; `reserved[24]` closes at 120. **[M: the assertion fails at compile time; it is what sent me to count.]** The fix and the next delta are the same eight bytes.
3. **`int64_t amount_minor` — money in minor units — is the authoritative quantity**, occupying exactly the eight bytes that were missing, so the row is now the 128 bytes §3.2 claims. §3.2 gives only `float amount`, inherited from osv's `Commitment`. A float cannot be what an exposure cap sums: §4.7 evaluates caps "as a fold over committed facts" and §5 claims integer folds are exact and portable across host and device. A cap fold over floats is not a fold by this store's own definition. `amount` stays for the judge's rendering and is never summed.
4. **A typed reason `not_authored_by_seam`.** §4.1's entry-class list has no reason for falsifier 17's refusal. Overloading `constraint_violated` would hide the one refusal the fourth law exists for.
5. **The cap's contribution is defined**: a fact contributes `max(0, after − before)` to its class's period — new exposure created, not gross turnover. §4.7 says "exposure caps per class per period" without saying what a fact contributes; a rewrite that lowers an amount must not refund the period.

Carried forward from R0.1 and still open: the `seg` and `warn` kinds, the ghost rule, the `$b64` tag, and the v0 float policy.

## §7 · What R0.2 does not do

The reply cache is in memory: §4.2 makes it "part of the replicated state machine", which needs R6. Quorum signatures are recorded in the class map and enforced at R5, so `quorum_insufficient` cannot yet fire. `pin_mismatch` and `stale_judgment` wait for a registered judge (R3) and a seam that emits margins (R4). The transactor is one thread, not §4.1's three (validate, commit, publish) — the shape is single-threaded and correct before it is concurrent. Still missing from R0 as a whole: **the client socket with length-prefixed frames** and **the fault injector**, which are R0.3, along with R0's two remaining gates — the acknowledgement half of the kill test, and a redelivered suffix that does not double-count.
